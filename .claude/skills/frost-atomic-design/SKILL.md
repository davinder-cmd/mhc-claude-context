# Frost Atomic Design

Standalone, narrow-trigger skill for one person: Brad Frost. Pulled out of the broader `design-systems` roster because his framework is already load-bearing infrastructure at MHC — the actual hierarchy and prefix convention in `design/_index.md` — not just a precedent to cite occasionally.

## How to use this skill

1. Use this when the question is a hierarchy-placement call: is this new UI element an atom, a component, a pattern, or a template? Frost's framework is the tiebreaker.
2. Reference `design/_index.md` directly alongside this skill — that file is where the framework is actually applied (Figma page prefixes `A_`/`C_`/`P_`/`T_`, the atoms/components/patterns/templates tables).
3. For anything else in the design-systems domain — governance, documentation structure, token architecture, other practitioners, comparisons to Material/Carbon/Polaris — use `design-systems` instead.
