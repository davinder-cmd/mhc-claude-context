Analysis · per program type

Assessment — clean fit, but use V2 ring (not V1)

You only have %, not session counts. V1 won't work — there's no "9 of 28." V2's progress ring is exact. The body line should reinforce that resuming is fast: "~5 min left" if you can compute it from average completion time, otherwise just "Resume assessment."

Journeys — clean fit, V1

Three signals (journeyStatus, pctComplete, levelsComplete) give you everything. Use journeyStatus = "In progress" as the inclusion gate, V1 step rail with levelsComplete / totalLevels, and the body line shows the next level title. Pct goes into the inline progress bar.

DCP — clean fit, V1

Same shape as Journeys. DTxTopicStatus = "Ongoing" is the inclusion gate. Topics complete / total goes on the rail. DTxTopicPctComplete is for the inline bar.

Challenges — fits with a new rail variant

Challenges aren't really "pick up where you left off" — they're time-boxed. The signal that matters is "hurry, X days left." Use a "days-left" rail (V-new) that flips to a warning color when daysLeft ≤ 3. Body line shows leaderboard rank + a quick activity stat. Drop the inline progress bar — it's not relevant.

Edge case: "Always-on" challenges with no end date should probably go in a different section ("This week's competitions") rather than this rail. The rail's whole premise is that there's a thing to finish.

Health Habits — wrong section

Habits don't end. visibleToUser = true is true forever; there's no "completion" state. Putting them here is a category error: "Pick up where you left off" implies a destination. Habits don't have one.

Concretely:

  • The streak is the whole point — and a streak displayed in a "things to finish" list visually conflicts with "12 of 28 sessions" right next to it. The user reads "12" as comparable when it's not.
  • Re-engagement is differently shaped. A habit user who hasn't checked in today doesn't need "resume" — they need "check in for today", which is a TODAY action, not a long-running thread.
  • The dismiss model breaks. "Hide for 30 days" makes sense for a program someone's drifting from. "Hide my hydration habit" doesn't — they signed up for it.

Better home for habits: a dedicated "Today's habits" tile (separate block, similar height to the Today strip) with the streak and a per-habit check-in button. Or, fold them into the Today / This-week section since they share a daily cadence.

Inclusion priority within the rail

Server should pre-sort cards in this order, then truncate to 3:

  1. Focus-matched + ongoing (DCP / Journey / Assessment)
  2. Challenge with daysLeft ≤ 3 (urgency wins)
  3. Other ongoing programs (DCP / Journey / Assessment), most recently active first
  4. Other challenges

One template, four rail variants

The shared markup carries a data-rail attribute. The mustache template renders the right rail block server-side based on program type:

  • data-rail="step" — Journeys, DCP
  • data-rail="pct" — Assessments
  • data-rail="days" — Challenges
  • (data-rail="streak" — defined for habits but not used in this section)
