Responsive variants

All three of these screens (Enroll, Lab work, Deadline) are the same template: app bar → title → focal card → progress/steps → support rail. The only real responsive question is how the image card behaves and whether there's a side rail. Same HTML in every tile below — only the CSS differs. Open each and resize to feel the reflow.

💡 Recommendation: Variant 2 — Split hero + rail. It's the "horizontal card on desktop, vertical card on mobile" pattern you described, keeps the support rail useful on wide screens, and reads calm on phones. Variant 3 is the fallback if we'd rather drop the rail for a simpler, single-column build.
Variant 1 Stacked + rail (baseline) Image card is a vertical banner at every width. Main + support rail on desktop. Mobile: stacked · Desktop: stacked, tall banner Safest, most consistent — but the image eats vertical space on desktop. Open ↗
Variant 2 · recommended Split hero on desktop Same card reflows: image left ~46% / content right on desktop; stacks vertically on mobile. Mobile: vertical card · Desktop: horizontal hero Matches the homepage horizontal card; less vertical bulk; rail retained. Open ↗
Variant 3 One calm column, no rail Single centered reading column (~680px) at all widths. Support + About fold to the bottom. Mobile: stacked · Desktop: same column, centered Calmest, least to configure — trades away the desktop rail + wide space. Open ↗
Variant 4 Compact thumbnail + rail Card reflows to a smaller image (~34%) beside content on desktop — a dashboard tile, not a hero. Mobile: vertical card · Desktop: thumbnail row Densest; good if the image should feel secondary to the task. Open ↗

One stylesheet (base.css) + a per-variant override (v1–v4.css). The markup in 01-v1…v4.html is identical — proving a single template carries every page. Pages without an image (deadline alerts, active/phase, records) use the same shell; their focal is a text/alert/phase card, so the reflow simply doesn't apply.
