The path at the first and last session

The middle state you've seen. The ends behave differently: at the start there's nothing completed to show; near the finish there's too much. One windowing rule handles all three — and the last state gets to lean into the finish, because that's where motivation peaks.

The one windowing rule

  1. Always show the current session, clearly marked.
  2. Show a little context around it — the session just finished, and the next locked one.
  3. Collapse a long run of finished sessions into a single "Sessions 1–N complete ✓" row (tap to expand).
  4. Always offer "See all N sessions." Never render all 10 rows inline.
  5. At the final session, cap the path with a finish marker — the visual end of the road is the payout.

Why the ends differ

What changes at each end — and why

First → make starting effortless

Nothing to celebrate yet, so the path invites rather than rewards: a clear "Start," two locked previews for shape. The reward is mentioned once, gently — the health reason leads.

Middle → hold a tight window

As sessions pile up, only the immediately-prior one stays for context. The window never grows; "See all" absorbs the rest. Working memory stays protected.

Last → lean into the finish

Motivation peaks here (goal-gradient), so this is the one place the reward cue can strengthen. The collapsed summary clears the clutter; the finish marker turns the end of the list into the celebration to come.

UX basis: Serial Position Effect (first & last are the most-remembered — design them deliberately), Goal-Gradient (motivation rises toward the goal — strengthen the reward cue only at the end), Peak-End Rule (the finish is the peak; the marker sets up the completion screen), Miller's Law (collapse long completed runs). The finish marker connects the path directly to the completion celebration (v3). Path edge-states v1 — for reaction.
