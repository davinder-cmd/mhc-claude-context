MHC Home — 7 Wireframe Experiments

v1 · 2026-05-06 · Block fidelity · Desktop 1200 + Mobile 375

Seven structurally distinct takes on the home page, each built from the same locked spine (single hero, 4 tracker tiles, source-labeled lanes, etc. per section inventory). Variables tested are sequence, weight, and topology — not the section vocabulary. UI applies in a later pass.

Each experiment leads with a thesis ("what's it testing"), shows desktop and mobile blocks side-by-side at proportional weights, and notes reflow + when-it-wins. Block fidelity is intentional — the reference doc says match fidelity to the decision; this stage is about sequencing and visual weight, not content polish.

Reflow decisions

  • Lanes (7+8): 50/50 desktop → stacked mobile (employer first per spine ranking, but here interest beats employer because the personalization signal is the bigger differentiator)
  • Tracker: 4-tile row desktop → 2×2 grid mobile

When this wins · risks

Wins when: first ship · low risk · users learn page once and it stays predictable · easy CMS · easy A/B baseline.

Risks: long flat middle (sections 5–10 all read at similar weight) · hero does most of the work; if hero allocation is weak the rest of the page won't compensate · "spotted-pattern" users (came for a specific item) have to scroll past everything.

EXP 05

Two-Column Desktop · Momentum / Discovery

Thesis: Below the hero, desktop splits into two columns. Left (~60%) = Momentum — your programs, your tracker, your insights, your challenge state. Right (~40%) = Discovery — what your employer wants you to see, content matched to your interests, optional rewards. Mobile collapses to a single stack with momentum first. Tests: does a topology change reduce the "long flat middle" the reference flagged, and does it satisfy both CS (employer prominence) and member (programs prominence) needs simultaneously?

Reflow decisions

  • Section order on mobile: momentum (4, 5, 6) → discovery (8, 7) → conditional (9, 10). reorder from desktop right-column position — but justified: vertical mobile beats by relevance, not by horizontal column.

When this wins · risks

Risks: 2-col layouts are heavier engineering · the 60/40 split may feel uneven at narrow desktop (912 with left nav present); could fall back to single-column at that breakpoint · users scan top-to-bottom by default — right column may be under-scanned (NN/g F-pattern caveat) · doubles the design surface to maintain.

Reflow decisions

  • Combined module: 4 tiles in a row + insight beneath desktop → tiles 2×2 + insight beneath mobile (collapse)
  • Insight states: when no insight (Hidden state from inventory), the module renders as a tracker-only card — no awkward empty insight area

When this wins · risks

Wins when: compactness is a goal (mobile-first thinking) · teams want to ship fewer surfaces · the AI Insights pattern works best tied to the data, not separated · home page length is a known complaint.

Risks: the AI Insights differentiator becomes less prominent visually (vs. its own band) · the Hidden insight state feels like dead vertical space inside the module unless treated carefully · couples two different teams' data (tracker + AI server) into one render — sync edge cases compound.

EXP 07

Rewards Forward · Engagement-Heavy Client Variant

Thesis: For clients with multi-type reward configurations (gift cards + points + raffles + store credit), rewards is a primary engagement lever — not a footer afterthought. This variant lifts the rewards summary above the lanes, in the slot right after tracker/insights. The 4-metric row demonstrates MHC's configurability moat — competitors only do points; we accommodate up to four reward types in one client setup. Tests: does promoting rewards to weight 3 with elevated placement work for engagement-heavy clients without overwhelming the rest of the page? Note: this is a per-client variant, not the default — Framing 1 (points-only) and zero-rewards clients still default to Experiment 1.

When this wins · risks
