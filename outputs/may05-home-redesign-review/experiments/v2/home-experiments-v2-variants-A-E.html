MHC Home — v2 Variants A–E · Personalization Forward

v2 variants · 2026-05-06 · Block fidelity · Desktop 1200 + Mobile 375

Five variants of the v2 personalization-forward direction. The prominence ranking (Hero w5 · Things I care about w4 · From your employer w4 · Programs DCP-only w3 · Tracker+Insights paired w3 · Challenges/Rewards/Greeting w2 · Nav w1) is held constant across all five. What varies is composition — how the lanes are arranged, where the personalization signal lives, and how the layout adapts to data sparsity.

The v2 baseline (paired 50/50 lanes immediately below hero, see v2 baseline file) is the reference point. Each variant departs on one specific axis. UI applies in a later pass to the variants that earn it.

Held constant across all 5 variants:
  • Hero is w5, single image card, 50/50 split (or compressed continuity for variant D)
  • Lanes "Things I care about" + "From your employer" are both w4 (promoted from v1's w3)
  • Programs is w3 and DCPs only — no journeys, no habits, no in-progress challenges
  • Tracker + Insights are paired into one combined module, mid-page, w3
  • Challenges (conditional), Rewards (optional), Greeting all stay w2; nav stays w1
  • 508 a11y, skeletons over spinners, sync-state per tracker tile, source labeling on all content surfaces

When this wins · risks

Wins when: each lane has rich content (4+ items consistently) · clients want each section to feel complete on its own · F-pattern + layer-cake scan beats compare-side-by-side on this page · hero allocation is solid enough that members reach the lanes anyway.

Trigger rules · when each state renders

  • Rich state (v2 baseline · paired lanes): Things I care about ≥ 3 items AND From your employer ≥ 2 items
  • Sparse state (merged card): Things I care about ≤ 2 items OR From your employer ≤ 1 items
  • Empty state (different — not shown): 0 interest items AND 0 employer items → section hides entirely; consider a "Tell us what you care about" prompt at top of page
  • Source tags (INT/EMP) on every item are non-negotiable in sparse state — the personalization signal still has to land

When this wins · risks

Wins when: client populations have wide variance in interest engagement (some users complete onboarding richly, others don't) · employer message frequency varies by client (some clients post 4/week, some 0) · the home shouldn't look broken when data is thin · empty-lane risk in v1 + v2 baseline is a real CS concern.

Risks: two compositions = two designs to maintain · stakeholders may resist a "graceful degradation" framing because it admits the rich state isn't always achievable · merged card can feel like a single column of mixed items — UI separation needs to do more work · trigger rules need clear edge-case handling (what about 3 interest + 0 employer?).

VAR 2.F

Calm & Scannable readability bet

Thesis (direct response to "v2 was too dense"): Hold the v2 prominence ranking exactly. Then strip everything that wasn't earning its place. Fewer items per section (2 per lane, not 4). Bigger items with more internal padding. Generous gaps between sections — sections are visibly separated by whitespace, not by colored borders. Soft color treatment — only soft fills, no saturated borders + saturated fills together. One CTA per section, not multiple. The page does less; what it does, it does at a readable scale. Tests: does scannability beat completeness for the home page?

v2 baseline (too dense)

  • Lanes paired 50/50, 2 items each = 4 items in fold's second band
  • Tracker tile row + AI insight + CTA + meta line stacked tightly in one module
  • Programs 3-up cards with progress + reward inline
  • Saturated colored borders + saturated fills on every section
  • Section-to-section gap: ~4–6px (touching)
  • Multiple inline reward refs visible per viewport

v2.F (calm & scannable)

  • Lanes paired 50/50, 1 item each + see-all = 2 items in fold's second band
  • Tracker tiles only — bigger numbers, AI insight as its own calm row below
  • Programs 1 featured DCP + see-all link (not 3-up grid)
  • Soft fills only; lighter left-border accent (3px not 4px)
  • Section-to-section gap: 16–20px (visible breathing room)
  • Reward refs once per item, smaller weight

What changed from v2 baseline (the dense version)

  • Lanes: 2 items per side → 1 item per side + a clear "+ See N more" link · the lane header still names how many total items exist, so users don't feel content is hidden
  • Programs: 3-up DCP cards → 1 featured DCP + see-all link · most engaged DCP gets the spotlight; rest accessible in one tap
  • Tracker module: bigger numbers, more padding, AI insight has its own row with breathing space (not crammed under the tiles)
  • Visual treatment: soft fills only · 3px left-border accent (was 4px) · 6px gap between sections (was 0–4px) · taller blocks but less stuff inside
  • One CTA per section. Hero has one primary CTA. Lanes have one item + see-all. Programs has one Continue + see-all.

When this wins · risks

Wins when: readability is the design goal · the home page is meant to feel calm and personal, not informational · members come back to the page often (so seeing the same single featured item is actually fine — they remember the rest is one tap away) · supports layer-cake scanning (NN/g pattern that applies to most home pages) · easier to apply UI to · easier on mobile.

Risks: stakeholders may feel "we're hiding content" · "+ See more" patterns shift behavior to a list page; need that page to be good · for clients with rich content, single-item-per-lane feels thin → may need a per-client config to expand to 2 items · sales demos may want to show more configured items at once.

Applying this principle to the other variants

The calm/scannable principle isn't tied to this variant — it's a treatment that can be applied to any of 2.A–2.E. If 2.F earns the UI investment, the principle should be the new house default for v2 work, not just one variant.

  • 2.A (Stacked) + calm: 4-up grids become 2-up grids; full-width treatment lets each item breathe more
  • 2.B (Greeting Fusion) + calm: chips less saturated; greeting line gets more vertical padding
  • 2.C (Two-Column) + calm: right column shows 1 item per lane, not 2
  • 2.D (Hero Continuity) + calm: drop the bottom border thickness; lighter source-tag weight
  • 2.E (Adaptive) + calm: rich state already follows calm rules; sparse state is naturally calm

Counts at-a-glance

Number of distinct content items visible above the fold (desktop):

  • v2 baseline: ~9 items (hero + 4 lane items + 4 tracker tiles)
  • v2.F (calm): ~6 items (hero + 2 lane items + 4 tracker tiles)

That's a 33% reduction in fold density without losing any structural element. Same sections, same ranking, fewer items per section.

Updated recommendation (after readability feedback):
  1. 2.F (Calm & Scannable) — apply first. Direct response to "v2 was too dense." Treats readability as the design goal and demonstrates the v2 ranking can hold while shedding ~33% of fold-density. The calm/scannable principle should become the house default for v2 work — apply it on top of any other variant rather than treating it as a separate option.

Hold 2.A (Stacked), 2.B (Greeting Fusion), and 2.C (Two-Column) at block fidelity. 2.B is still trivially additive on top of any chosen baseline; we can fold it in once 2.F or another base is committed. The path forward is commit to calm, then layer one structural variant on top — not run all five in parallel.
