Rewards display · 5 variations

Five takes on the "Your rewards" section from the v2 personalization-forward prototype. Same content (gift card · points · raffle entries · store credit), same v6 warm-neutral + SF Pro language. What varies: arrangement, color treatment, density, container shape, and macro layout. Each variation is labeled and rendered in full so you can pick.

V1

Icons

Same 4-up tile grid as the baseline. Each tile gets a small line icon at the top — gift, star, ticket, store. Icons are quiet (text-secondary, 1.5px stroke) so they support the type without competing.

What it adds

Faster pre-attentive recognition — members can identify "raffle" or "gift card" by glance shape before reading the label. Useful when the rewards block is glanced quickly.

Risks

Icons must be drawn consistently in production (stroke weight, optical balance). Generic line icons can read "wellness app" rather than clinical-modern; consider commissioning custom or constraining to one icon library.

V2

Color wash

Each tile gets a soft colored background tied to its reward type — warm (gift card), primary (points), lavender (raffle), moss (store). Labels match family. Wash stays at 50-stop so saturation stays calm and surfaces remain warm-led.

What it adds

Each reward type has a distinct identity, easier to remember and locate ("the green one is store credit"). Reinforces multi-type as the differentiator — visually obvious there are four economies, not one.

Risks

Pushes the page chromatic budget. The 60/30/10 audit shifts — warm-led surfaces get 4 simultaneous chromatic accents in one band. Mixes lavender + moss + warm + primary which is normally avoided in v6 (no purple as background; no rose either). Most aggressive color move on the home page.

V3

Single container

All four rewards inside one card with thin internal vertical dividers. Reads as a single "rewards summary" moment instead of four separate moments. Bigger numbers (28px) earned by the consolidated container.

What it adds

Consolidated. Reads as one component instead of four. Saves vertical space (one container's padding instead of four). Bigger value type because the container can absorb the visual weight without each tile competing.

Risks

Less differentiation between reward types. On mobile when the row collapses to 2-up, the dividers feel awkward (need to handle the wrap explicitly). Doesn't naturally accommodate per-tile actions ("Spend in store →" CTA per cell would crowd).

V4

Vertical list

Stacked rows · icon (washed in family color) · label + meta · value (right-aligned). Reads more like a transactions list. Most scannable on mobile; takes more vertical real estate on desktop.

What it adds

Strongest mobile pattern — list rows already stack naturally at any width. Easy to add per-row actions (Continue, Redeem) without crowding. Family color stays small (just inside the icon chip), so the chromatic budget stays tight.

Risks

Takes 4 rows of vertical space on desktop where 4 tiles would take 1 row. May read as "transaction history" rather than "your rewards summary" — values are small relative to a tile. Less of a "look at this" moment.

V5

Three columns · Continue / Challenge / Rewards

Restructure the bottom of the page. Three sibling columns instead of three stacked sections — Continue your programs (60%) · Your challenge (20%) · Your rewards (20%). Programs gets more horizontal weight (the most engagement-relevant); challenge and rewards become compact glance-cards on the right.
