Mobile annotations
  • One hero only — no carousel, no peek-card. JH explicit. The single hero gets one priority moment per session.
  • Ongoing programs sit above the personalized lane, not buried at the bottom. CS asked for "easier access" — that means high in the stack.
  • Wellbeing-interest chips are existing data, surfaced as a filter mechanism on this lane only (not page-level). Tap "Edit" to adjust interests; chip taps filter which items show. The pill anchors only the Interests section, never the whole page (per direction update 03).
  • Per-item interest tags inline (e.g. "Sleep" tag on each card) make the filter audit-able — user can see which interest drove which item.
  • Conditional modules are visually striped with a dashed orange left border and italic "Conditional" label. They are intentionally distinguishable so reviewers can decide inclusion without confusing them with required modules.
  • No rewards module in iteration 1. Rewards-focused home is a future iteration. v1 had a persistent chip + slim-row — both removed.
  • No DCP progress card with clinical metric. DCP-focused home is a future iteration. The "Continue session 3 of 8" continuity is preserved inside the Ongoing Programs module — that's a CS-required surface, separate from the DCP-progress-with-metric card I had in v1.

What's deliberately not in iteration 1

  • No persistent rewards header chip. Was in v1; out now. "Rewards focused home screen" is a future iteration per the canonical doc.
  • No rewards slim-row module. Same reason.
  • No DCP Progress card with inline clinical metric. "DCP focused home screen" is a future iteration. Continuity is preserved inside the Ongoing Programs module — that's the CS-required surface, not a clinical-metric proof card.
  • No dots-carousel hero. JH explicit: one hero image. Closed.
  • No new mandatory focus picker. Wellbeing interests is existing data, not a new onboarding step.
  • No Chat Advisor card pattern (separate from the conditional DCP AI Coach module). Out of doc scope.
  • No Welcome banner. Greeting headline does the same job.
  • No biometrics on home. Clinical screening data is detail-screen only.
  • No Trophy Case / achievements gallery. Future small follow-up.

Open questions still to resolve

  • DCP AI Coach entry — in or out for iteration 1? Doc flags as open. Wireframe shows it in the conditional row; remove if leadership says future-iteration.
  • Tracker data + Tracker Insights — keep, remove, or relocate? Both currently in production. Wireframe keeps them in the conditional row to make the design easy to ship as-is or strip down. Recommend keeping both — removal would be a regression.
  • Wellbeing interests data state — populated for all members? If not, the muted "+ Edit interests" chip becomes the lane's empty state instead of just an action affordance. Confirm with CS.
  • Hero source — what fills it on a typical day? Doc says "one hero image." Doesn't say what populates it. Recommendation: priority engine (active challenge → client priority → interest-related content) — same logic the lanes use, applied to one slot.
  • Ongoing programs — what's the cap? Wireframe shows 2 (mobile) / 3 (Scenario A) / 4 (Scenario B). What if a user has 6 ongoing things? Recommend "+ N more" chip after the cap, routing to a dedicated screen.

Net engineering ask

Zero new Page Layout Elements required for iteration 1. All seven required modules (top nav, greeting, hero, ongoing programs, employer lane, interests lane with filter chips, bottom-nav/chrome) assemble from existing HTML containers, Lists, Buttons, and User Inputs. The eng-named "full browser page" requirement is a layout/CSS concern — Innovations / Eng confirm CSS scaffold supports unbounded width.

Net effect: this iteration ships without queuing a new building block. If we keep the conditional modules in too (Tracker data, Tracker Insights, DCP AI Coach), all of those exist in production today.
