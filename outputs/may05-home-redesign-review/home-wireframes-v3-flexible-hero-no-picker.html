02Hero presentation · current ship vs future (John's actual concern)

John's beef with the carousel was never multiplicity — it's that the current presentation is messy. Recent designs use single-card with left/right arrows below; older designs use peek-cards (where the next card pokes in from the side). Both read as unfinished. The right answer: one card visible at a time, dots below, swipe to advance. Same approach for mobile and desktop when eng can build it. For iteration 1, ship single committed hero only.

Mobile annotations
  • Hero is one card, flexible content. Tagged with content-type label ("Active challenge") above the title so the user reads what kind of moment this is.
  • Tracker tiles 2×2: Steps · Sleep · Calories · Active Min. Calories replaces Heart Rate per direction update.
  • Insights placed right after tracker data — bridges raw numbers to interpretation. Both required, both currently in production.
  • Reward references inline on items — "$100 at completion," "+50 pts to attend," "+5 pts each." No persistent rewards chip in chrome. Multiple reward types accommodate without UI complexity.
  • "Things I care about" has a one-line explainer ("Based on interests you picked at onboarding · Edit in profile") so the user can audit why this content is showing without us re-asking. Edit goes to profile, not a mid-page chip selector.
  • Per-item interest tag ("Sleep", "Stress", "Move more") shows which onboarding interest pulled each item — even more legible than the section label alone.
  • Hero future state annotated in italic at the bottom of the hero block — reviewers see the trajectory without it being designed yet.
  • 508: hero copy never overlays the photo. All source labels use color + text. Tap targets ≥ 44 px.

What's deliberately not in v3

  • No mandatory focus picker.
  • No page-level focus pill.
  • No mid-page filter chips on the personalized section.
  • No persistent rewards chip in chrome (rewards referenced contextually instead).
  • No spine-level rewards module (rewards-focused home is a future iteration per canonical doc).
  • No DCP Progress card with inline clinical metric (DCP-focused home is a future iteration).
  • No nav design — handled by separate spec.

Open questions still surfaced

  • Hero variants — confirm with sales + client services. Davinder named this explicitly. The five-variant slot accommodates the use cases that would otherwise get killed if hero locked to interests. Validate with the people who'd use it.
  • Hero source-tag treatment. Current design uses a colored uppercase label above the title ("Active challenge", "Open enrollment", "New on MHC", etc.). Confirm this reads as editorial, not as a UI badge. Worth a usability check with 3–5 users.
  • "Edit in profile" target. The Interests section explainer routes to profile for interest editing. Confirm this path exists today (Personify pattern) — if not, it's a small but real eng ask to wire up.
  • Hero at small mobile widths. The 50/50 split crops vertically on mobile (image stays in top half). Confirm photo brief works at this crop — eyes/face in the top-third of the source image.
  • New challenge hint placement on 1080. Currently a one-line note below the 3-up programs row. Test: does it earn its place, or should it be a fourth tile that bumps to the next row?

Net engineering ask

Zero new Page Layout Elements for iteration 1. Same as v2. Carousel future state is queued behind the nav rebuild — not a blocker for iter 1.
