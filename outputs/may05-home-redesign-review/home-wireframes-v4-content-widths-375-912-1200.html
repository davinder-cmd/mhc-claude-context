Corrected breakpoints. v3 modeled 1600 px wide which assumed nav-on-top or a wider-than-current viewport — not real for V1. v4 designs the content area at three actual widths: mobile 375, current desktop 912 (with left nav still on), and 1200 max. Chrome (top nav vs. left rail) is handled separately by the nav spec — these wireframes only design the content area at each width. Also applies the May 6 personalization treatment: "Your interests: Sleep · Stress · Move more · [Edit]" with inline edit modal on home (not a profile detour).

02"Things I care about" · sub-header + edit modalMay 6 personalization treatment

The personalization story is "we listened." The section sub-header lists the user's actual onboarding interests by name — proof of listening. [Edit] opens a modal sheet on home (not a detour to profile) where the user can adjust their interests. This is edit, not pick — the user already has values; we're letting them adjust.

The implicit causal phrase "Here are your interests, and because of that, here's what you're seeing" doesn't need to be written — the layout (interests above, content below) carries the meaning.

Why this isn't a picker — Picker is mandatory, modal-on-load, page-reframing, "pick the one thing." Edit is voluntary, opened by tap, scopes one section's content, "adjust the things you said you care about." Reuses the existing interests-management UI from onboarding/profile — no new component, just a new entry point.

What's deliberately not in v4

  • No 1600 wide artboard. v3's wide breakpoint was based on Jill's nav-on-top assumption that doesn't apply for V1. 1200 is the max content width.
  • No mandatory focus picker.
  • No persistent rewards chip in chrome.
  • No DCP-progress card with inline clinical metric (DCP-focused home is a future iteration).
  • No nav design — handled by separate spec.

Key open items still on the list

  • Hero allocation rules — confirm priority engine logic + employer must-show + floor allocation with sales / client services. See 07 for talking points.
  • Edit modal mechanics — confirm the existing interests-management UI (from onboarding/profile) can be invoked as a modal sheet from home.
  • Ongoing programs cap — what if user has more than 4 programs? Need an "+N more" overflow.
  • Hero photo brief at mobile crop — confirm photographers have a "subject in top-third" guideline.

Net engineering ask

Zero new Page Layout Elements for V1. Same as v2/v3. Edit modal reuses the existing interests-management UI from onboarding/profile — new entry point only.
