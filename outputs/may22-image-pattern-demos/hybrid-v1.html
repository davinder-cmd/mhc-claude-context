Hybrid · aspect-ratio + max-height

Aspect-ratio locked below the crossover width. Height-capped above it. Reasonable on mobile, controlled on desktop — the best of both. This is what Material does on its larger heroes.

Try it: drag the browser narrower and wider. Watch the readout (bottom right) switch between aspect-ratio (16:9) and max-height (480px). The crossover happens around 853px — below that, height shrinks with width; above it, height locks at 480px and only width keeps growing.

The crossover math

With aspect-ratio: 16/9 and max-height: 480px, the crossover sits at 853px wide (because 853 × 9/16 ≈ 480). Below 853, the ratio rule wins. Above 853, the cap rule wins.

The CSS

.hero { width: 100%; aspect-ratio: 16 / 9; /* governs at small widths */ max-height: 480px; /* governs at large widths */ overflow: hidden; } .hero img { width: 100%; height: 100%; object-fit: cover; /* photo fills, crops as needed */ }
This is what you noticed in Material. Height grows with width up to a point, then locks. Above the cap, the image crops more on top/bottom as the container gets wider. Below the cap, the image stays in pure 16:9. One container, two behaviors, no media queries needed — the browser does the switching automatically.
When to use this over pure aspect-ratio: any time a 16:9 image would become uncomfortably tall at large widths. A 16:9 hero at 1440px wide is 810px tall — that pushes everything else below the fold. The cap stops that. Use this for full-bleed heroes; use Pattern 1 (pure ratio) for column-constrained cards.
